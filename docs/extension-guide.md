# 新增审核页面与业务扩展手册

本手册中的 `PageAdapter`（页面适配器）负责 DOM（页面文档对象模型）采集，`PageAction`（页面动作）负责受控写回，`Renderer`（渲染器）负责界面展示，`Profile`（业务配置档案）负责选择后端业务能力。

## 只新增页面

先建立页面身份探测和 `PageAdapter`，把页面字段映射为标准 `PageData`；再注册需要的页面动作和回读器；最后为任务类型选择或新增 Renderer。不要修改后端规则，也不要在组件里加入页面选择器。

## 新增审核业务

先确定业务边界和 Profile，再复用现有能力。只有业务确实需要新判断时，才增加 CapabilitySpec、Handler 或子图，并将结果映射为通用事实、检查结果和审核任务。主图保持不变。

## 交付清单

- Profile、启停状态和字段需求。
- 能力输入输出契约、超时和降级策略。
- 注册表条目及唯一 ID。
- 页面 Adapter、Action 和 Renderer（如需要）。
- 正常、缺材料、冲突、超时和人工复核测试。
- 业务规则、结构图和迁移说明。

## 禁止事项

- 复制一套按城市命名的主图。
- 在 React 组件中计算后端资格规则。
- 在后端写 DOM 选择器或依赖浏览器全局变量。
- 通过 `Any`、未注册字符串或隐式字段绕过契约。
- 恢复 `review-extension/public/*.js` 旧双源码或已停用过户 Profile。

## 页面适配器契约

适配器至少实现页面身份探测、字段采集、材料候选收集和采集诊断四项能力，并返回页面 URL、业务标识和采集时间。字段映射使用后端约定的规范字段名；无法确定的值返回缺失和来源信息，不猜测填充。动作控制器必须声明动作 ID、目标字段、允许的页面身份、写入方式和回滚方式。

## 验收示例

新增页面完成后，应能在无后端规则改动的情况下：打开页面并识别 Profile、提交标准 `ReviewRequest`、展示现有任务渲染器、拒绝不属于该页面的写回动作，并在页面刷新后重新采集验证写入结果。

页面的状态颜色、冲突标红、证据来源、图片定位、字段回填高亮和页面失效提示必须遵守[审核工作台前端展示规范](frontend-presentation.md)。新增页面可以增加材料或字段标签，但不能重新定义 `MATCH`、`CONFLICT`、`INSUFFICIENT` 的视觉含义。

## 推荐实施顺序

### 阶段一：页面勘察

记录页面 URL 模式、唯一业务标识、字段所在区域、材料卡片结构、分页和登录状态。把不稳定的 CSS class、虚拟列表和异步加载情况写入 Adapter 设计说明，不要先在组件里试探式拼接选择器。

### 阶段二：采集适配

实现 `detectPage()`、`collectFields()`、`collectMaterials()` 和 `diagnostics()`。所有采集结果带 `source`、`raw_label`、`collected_at` 和可选的置信度。采集失败返回诊断项，让后端决定是否缺材料；Adapter 不把失败伪装成空字符串。

### 阶段三：动作和展示

为每个写回动作定义前置条件、目标字段、允许页面、原值校验、回读方式和回滚策略。任务展示通过 `RendererRegistry` 按 `task.type` 选择，通用任务使用默认渲染器；只有交互明显不同才新增渲染器。

### 阶段四：联调和发布

先使用脱敏页面快照进行 Adapter 单测，再使用浏览器集成测试验证真实 DOM。确认页面刷新、重复点击、网络重试、标签页切换和权限拒绝行为。构建后只发布 `dist` 产物，不把临时调试脚本放回 `public`。

## 页面到 Profile 的映射

页面 Adapter 只上报页面身份和业务候选，最终 Profile 由后端 `BusinessRegistry` 结合租户、地区和启用状态选择。前端不得根据 URL 自己决定政策版本；如果页面身份无法唯一确认，应显示“无法安全识别页面”，禁止写回。

## 业务交付文档要求

每个已配置的审核 Profile 都必须有一份独立业务文档，至少包含：Profile 标识和版本、BusinessRegistry 条目、CapabilityRegistry 绑定、BusinessRule/ExternalCheck 条目、子图或 Handler 映射、PageAdapter、PageAction、Renderer、字段材料规则、状态展示、页面定位和回填行为。通用注册表文档解释机制，地区业务文档解释实际绑定；二者缺一不可。
