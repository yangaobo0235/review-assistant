# 当前业务规则

本文件中的 `Profile`（业务配置档案）表示业务、地区和版本的组合；`MATCH`（一致）、`CONFLICT`（冲突）、`INSUFFICIENT`（证据不足）和 `REVIEW_REQUIRED`（需要人工复核）是系统统一状态。具体英文术语见[术语对照表](glossary.md)。

## 生产 Profile

- `qingdao_scrap_replacement`：青岛报废置换。
- `changchun_scrap_replacement`：长春报废置换。
- 车源和一致性当前保持未配置或人工复核入口。
- 过户能力已停用，不得重新注册为生产能力。

各个复杂业务使用独立规则文档，避免不同地区的日期、材料和页面差异混在一张表里：

- [青岛报废置换审核规则](business-rules/qingdao-scrap-replacement.md)
- [长春报废置换审核规则](business-rules/changchun-scrap-replacement.md)
- [新增业务规则文档模板](business-rules/template.md)

本文件负责解释跨地区的共同规则和状态语义；地区文档负责记录可以直接执行的完整配置，包括前端行为、后端字段、材料、能力、政策、任务和写回动作。以后新增地区或审核页面，原则上新增一个独立 Markdown 文件，并在本索引中登记，不要把多个地区的细节继续堆进本文件。

## 字段域

标准字段按 `application.*`、`old_vehicle.*`、`new_vehicle.*`、`scrap_certificate.*`、`invoice.*` 和 `page_ocr.*` 组织。跨材料判断只能引用规范字段和证据来源，不能依赖 OCR 原始文本的偶然格式。

## 判断语义

`MATCH` 表示证据充分且一致；`CONFLICT` 表示有效证据互相矛盾；`INSUFFICIENT` 表示缺少运行判断所需证据；`REVIEW_REQUIRED` 表示系统无法安全自动判定，必须人工确认。建议生成器必须保留触发任务和理由。

## 材料与核验

材料完整性先于业务规则执行。二维码核验必须记录载荷来源、解析状态和可信度；地区政策按 Profile 选择，不得由前端推断；主体关系和车辆字段比较需要跨文档证据，缺失时进入人工复核。

## 页面动作

页面写回只允许注册动作。执行前校验页面身份和唯一目标，写入后回读确认；失败时返回可见错误并尝试回滚。业务建议本身不能绕过动作白名单直接写 DOM。

## 规则执行顺序

1. 先确认页面和 Profile 有效，再确认材料是否满足能力的最低输入。
2. 对每份材料执行格式、来源、清晰度和时间有效性检查。
3. 将 OCR、二维码和人工录入统一规范化，保留原始来源和规范化过程。
4. 执行单材料规则，再执行跨材料字段比较和主体关系检查。
5. 汇总所有阻断项和待确认项，最后才计算建议。

早期阶段失败不能被后续“看起来正确”的字段覆盖。例如缺少报废证明时，即使车辆 VIN 与发票一致，也只能说明车辆字段匹配，不能给出材料完整的通过建议。

## 证据优先级

规则应优先使用可验证的结构化字段，其次使用高置信度 OCR，再使用人工确认值。不同来源产生冲突时，不得静默选择一个值；必须产生 `CONFLICT`，列出双方来源，并创建人工复核任务。证据过期、来源不明或无法定位原文时，状态为 `INSUFFICIENT`。

## Profile 变更

新增或调整地区政策、材料要求和阈值时，先创建新的规则或 Profile 版本，绑定到测试环境验证，再切换生产引用。不要直接修改正在使用的常量，以免历史任务无法重放。停用 Profile 后，新请求不得选择它，历史响应仍必须能够读取和解释。

## 业务规则验收清单

- 正常材料能够生成预期事实和任务。
- 任一关键材料缺失会生成明确缺失任务。
- 两份材料字段冲突会生成冲突任务而不是自动通过。
- 外部核验超时会记录降级并阻断自动通过。
- 前端只展示和执行后端返回的任务，不复制规则判断。

## 当前能力矩阵

| 能力 | 青岛报废置换 | 长春报废置换 | 结果用途 |
| --- | --- | --- | --- |
| 材料完整性 | 启用 | 启用 | 生成缺失材料任务 |
| 车辆字段比较 | 启用 | 启用 | 发现 VIN、车牌等冲突 |
| 发票与新车关系 | 按 Profile 配置 | 按 Profile 配置 | 形成跨材料事实 |
| 主体关系 | 启用/人工复核 | 启用/人工复核 | 判断申请人与材料主体关系 |
| 地区政策 | 青岛规则版本 | 长春规则版本 | 判断政策适用性 |
| 车源核验 | 未配置 | 未配置 | 不得自动通过 |
| 过户审核 | 停用 | 停用 | 不得进入生产计划 |

“未配置”和“停用”是不同状态：未配置表示未来可以通过注册流程接入，停用表示当前明确禁止执行。两者都不能被前端当作通过。

## 字段修改规则

新增字段前先确认它是否能由现有规范字段表达；能表达时扩展字段来源或证据，不创建同义字段。字段重命名必须提供别名转换和历史读取策略。字段删除前检查 Profile、能力、Renderer 和测试引用，并保留至少一个版本的兼容读取。
