# 报废置换材料专属 OCR 提示词与识别链路改造计划

> 状态：已实施并完成自动化验证。
>
> 编制日期：2026-09-13。
>
> 适用范围：青岛、长春 `scrap_replacement/{region}/1.0` 的材料识别环节。
>
> 参考资料：本次提供的旧车行驶证、旧车登记证、报废机动车回收证明、新车行驶证、新车登记证、机动车销售统一发票、营业执照，以及外部系统 `InvoiceOcrServiceImpl.java` 中的提示词写法。外部文件只作为分析参考，不直接复制其业务规则。

## 1. 改造目标

本次改造不以“增加一段更长的通用提示词”为目标，而是将当前材料识别升级为：

```text
页面上传位置提供预期材料类型
        ↓
选择该材料、该业务范围的专属提取提示词
        ↓
模型只提取图片中明确可见的原始事实和证据位置
        ↓
代码校验资料类型、字段结构和明显错位
        ↓
代码生成归一化值并执行确定性审核规则
```

需要解决的问题：

1. 减少多个证件规则同时进入一个提示词造成的字段串扰。
2. 避免把字段路径、字段标题或其他长编号当成识别值。
3. 明确发动机号码与发动机型号、发票号码与其他号码、注册日期与发证日期等易混淆字段。
4. 保留图片中的原始文字，归一化只用于比较，不污染证据展示。
5. 区分“版面没有该字段”“字段存在但看不清”“字段识别成功”。
6. 继续输出证据坐标，支持审核助手缩略图和查看原图。
7. 通过固定样本和结构化测试评估提示词效果，避免凭单次截图反复调词。

## 2. 本次不改造的范围

- 不改变现有 LangGraph 节点数量和节点顺序。
- 不把人工确认加入 LangGraph 中断、Checkpoint 或恢复流程。
- 不重新设计审核助手整体页面。
- 不改变六类车辆材料的必传规则和主体证件动态要求。
- 不让视觉模型直接作出“一致、冲突、通过、驳回”等审核结论。
- 不让视觉模型判断地区政策、二维码官网真实性或新旧车挂靠关系。
- 不提交本次提供的真实证件图片到 Git 仓库。

## 3. 当前实现评估

当前 `document_policies.py` 已经具备以下基础能力：

- 按资料类型维护字段白名单和识别指引；
- 要求纯 JSON 输出；
- 输出 `document_type`、`fields`、`confidence`、`evidence_regions`、`uncertain_fields`；
- 对日期、金额和字段名自回显进行约束；
- 针对低置信度、非法 JSON、资料类型不匹配等原因重试一次。

当前主要不足不是“完全没有专属提示词”，而是 Qwen 生产路径优先调用 `extract_unknown`：每张图片使用一个同时包含全部资料类型规则的提示词，由模型在一次调用中完成资料分类和字段提取。该路径会削弱已有专属策略的效果。

### 3.1 外部 Java 提示词可借鉴内容

- 图片旋转、倒置、倾斜时先确定阅读方向；
- 票面字段与结构化字段的明确映射；
- 对相似字段给出禁止混用说明；
- 限制纯 JSON，不输出解释或 Markdown；
- 对日期和金额规定格式；
- 明确排除无关字段。

### 3.2 外部 Java 提示词不能直接照搬的内容

1. 只覆盖二手车发票、机动车销售发票和回收证明，没有覆盖本项目全部资料。
2. 要求所有字段都返回、缺失时填空字符串，会混淆“没有”和“看不清”。
3. “选择最可能字段”的描述会鼓励猜测，不适合审核系统。
4. 没有证据坐标，不能支撑当前审核助手定位原图。
5. 发票代码与数电号码的规则和本项目页面兼容需求不同。
6. 直接提取大量审核无关字段，会增加串字段和耗时风险。

## 4. 设计原则

### 4.1 模型提取事实，代码执行规则

模型允许负责：

- 判断图片中的资料类型；
- 读取明确可见的字段原文；
- 标记看不清或存在字符歧义的字段；
- 返回字段所在图片区域；
- 返回整体识别置信度。

代码必须负责：

- 页面上传位置与材料类型校验；
- 字段允许来源选择；
- 日期、金额、车型、燃料类型、发动机型号归一化；
- 数电号码向页面字段的兼容映射；
- 页面值与材料值比较；
- 材料完整性、地区政策、二维码和主体关系结论；
- 是否进入人工处理。

### 4.2 原始值和归一化值分离

每条证据至少保留：

- `raw_value`：模型从图片读取的原始文字，用于审核助手展示；
- `normalized_value`：代码根据字段类型生成，只用于比较；
- `field`、`document_type`、`business_scope`；
- `image_id`、`image_index`、`evidence_region`；
- `confidence`、`uncertain`、`uncertainty_reason`。

例如：

```text
图片原文：重型半挂牵引车
归一化值：牵引车

图片原文：1SGe4-460
归一化值：ISGE4460

图片原文：￥355,000.00
归一化值：355000
```

审核助手展示原文，比较器使用归一化值。

### 4.3 不以字段数量判断识别质量

- 材料版面没有字段：不输出到 `fields`，也不写入 `uncertain_fields`。
- 字段明确存在但看不清：不猜值，将规范字段名写入 `uncertain_fields`。
- 字段清晰可见：输出原始值和证据区域。
- 只识别到一份真实有效材料证据时，仍按现有规则参与核验，不因数量少自动进入人工处理。

## 5. 材料与字段提取矩阵

专属提示词的白名单只决定“允许提取什么”，最终是否参与某个页面字段核验仍由 `field_evidence_policies.py` 决定。

### 5.1 旧车行驶证

| 规范字段 | 票面位置/文字 | 提取要求 |
| --- | --- | --- |
| `vehicle.type` | 车辆类型 | 保留完整原文，如“重型半挂牵引车” |
| `vehicle.plate_no` | 号牌号码 | 不读取档案编号或条形码数字 |
| `vehicle.owner` | 所有人 | 读取完整个人姓名或企业名称 |
| `vehicle.vin` | 车辆识别代号 VIN | 不读取车辆型号 |
| `vehicle.registration_date` | 注册日期 | 不得使用发证日期代替 |

禁止项：

- 发动机号码不能输出为发动机型号；
- 检验有效期不能输出为注册日期；
- 正反面拼接在一张图片中时，应分别读取对应区域，不因版式拼接而判定资料类型不明。

### 5.2 旧车机动车登记证书

| 规范字段 | 票面位置/文字 | 提取要求 |
| --- | --- | --- |
| `vehicle.type` | 注册登记机动车信息栏“车辆类型” | 保留完整原文 |
| `vehicle.vin` | 车辆识别代号/车架号码 | 与车辆型号、发动机号严格区分 |
| `vehicle.engine_model` | 第 12 项发动机型号 | 不能读取第 11 项发动机号码 |
| `vehicle.owner` | 注册登记/转移登记中的有效所有人 | 按下述所有人规则处理 |
| `registration.covered_pages` | 图片页脚印刷页码 | 只输出实际可见页码 |

登记证所有人规则：

1. 无转移登记时，读取注册登记信息栏的机动车所有人。
2. 存在转移登记时，读取最后一条明确、完整的转移登记所有人。
3. 如果当前图片中的转移登记栏已经写满、无法确认后续页是否还有记录，不得把最后可见记录直接认定为当前所有人，应标记 `vehicle.owner` 不确定。
4. 抵押、解除抵押、变更登记不是转移登记，不能作为所有人来源。
5. 所有人值不能混入身份证明号码、住所或登记日期。

### 5.3 报废机动车回收证明

| 规范字段 | 票面位置/文字 | 提取要求 |
| --- | --- | --- |
| `vehicle.type` | 车辆类型 | 保留完整原文 |
| `old_vehicle.recycle_date` | 交车日期 | 必须读取表格内真实日期 |
| `scrap_certificate.certificate_no` | 右上方回收证明编号 | 提取完整编号及分隔符 |
| `vehicle.vin` | 车辆识别代号 | 不读取二维码内容代替票面字段 |
| `vehicle.plate_no` | 车辆牌照号码 | 不读取条码数字 |
| `vehicle.owner` | 车主名称 | 读取完整主体名称 |

二维码由现有二维码工具独立解码和官网校验，视觉模型不负责猜测二维码 URL。

### 5.4 新车行驶证

| 规范字段 | 票面位置/文字 | 提取要求 |
| --- | --- | --- |
| `vehicle.plate_no` | 号牌号码 | 读取完整省份简称和号码 |
| `vehicle.vin` | 车辆识别代号 VIN | 不读取车辆型号 |
| `vehicle.owner` | 所有人 | 读取完整主体名称 |
| `vehicle.registration_date` | 注册日期 | 不使用发证日期或检验有效期 |

当前业务不使用行驶证推导新车燃料类型；即使背面存在燃料文字，也不加入该页面字段的有效证据集合。

### 5.5 新车机动车登记证书

| 规范字段 | 票面位置/文字 | 提取要求 |
| --- | --- | --- |
| `vehicle.fuel_type` | 第 13 项燃料种类 | 保留“天然气”“柴油”等原文 |
| `vehicle.vin` | 第 9 项车辆识别代号/车架号码 | 不读取车辆型号 |
| `vehicle.owner` | 注册登记信息栏机动车所有人 | 无转移登记时作为当前所有人 |
| `registration.covered_pages` | 图片页脚印刷页码 | 支持一张图片同时覆盖第 1、2 页 |

新车登记证中的发动机型号不参与“报废发动机型号”核验；注册日期仍按已确认业务规则只认新车行驶证。

### 5.6 机动车销售统一发票

| 规范字段 | 票面位置/文字 | 提取要求 |
| --- | --- | --- |
| `invoice.invoice_no` | 数电号码/发票号码 | 只读取票面对应标签后的完整号码 |
| `invoice.invoice_date` | 开票日期 | 不读取登记日期或其他日期 |
| `invoice.amount` | 价税合计（小写） | 不读取不含税价、税额或大写金额 |
| `new_vehicle.origin` | 产地 | 保留票面原文，如“青岛” |
| `vehicle.vin` | 车辆识别代号/车架号码 | 不读取合格证号 |
| `vehicle.owner` | 购买方名称 | 不得读取销货单位名称 |
| `invoice.terminal_certificate_no` | 购买方统一社会信用代码/身份证号码 | 不读取销售方纳税人识别号 |
| `invoice.phone` | 销货单位信息区域“电话” | 只读取“电话”标签对应值，不读取账号、税号、吨位或限乘人数 |

模型不再直接输出 `invoice.code`。页面兼容层按当前已确认业务规则处理：

```text
原始票面事实：invoice.invoice_no = 数电号码
页面兼容字段：invoice.code = invoice.invoice_no
页面兼容字段：invoice.invoice_no = invoice.invoice_no
```

该复制动作由确定性代码完成并标明“数电号码页面兼容映射”，不伪装成图片出现了两个字段。

### 5.7 营业执照

| 规范字段 | 票面位置/文字 | 提取要求 |
| --- | --- | --- |
| `business_license.company_name` | 名称 | 读取完整法定名称 |
| `business_license.legal_representative` | 法定代表人/负责人 | 保留实际标签和姓名，不混用登记机关经办人 |
| `business_license.unified_social_credit_code` | 统一社会信用代码 | 不读取二维码或其他登记编号 |

营业执照的识别结果只作为主体关系证据，不直接输出新旧车挂靠结论。

### 5.8 条件材料：身份证

继续维持最小化识别：

- `identity_card.side`：只能是 `FRONT` 或 `BACK`；
- `identity_card.name`：只在正面读取姓名；
- 不提取或记录身份证号码、地址、出生日期、民族和签发机关；
- 反面只用于确认材料正反面齐全。

## 6. 已确认的业务项

### 6.1 数电号码映射

本计划默认沿用当前已经确认的页面兼容行为：数电发票只有一个号码时，该号码同时用于页面“发票代码”和“发票号码”核验。

实现上改为“模型只提取一次，代码复制”，避免模型重复生成两个可能不一致的值。

### 6.2 终端客户手机号

已确认页面“终端客户手机号”使用机动车销售统一发票中明确标注的“电话”字段。本项目当前票面版式中，该字段位于销货单位信息区域。

识别规则：

- 只读取“电话”标签对应的值；
- 不读取账号、纳税人识别号、主管税务机关代码、吨位或限乘人数；
- 票面没有明确“电话”字段时不输出；
- 标签存在但号码看不清时写入 `uncertain_fields`，不得从其他数字猜测。

## 7. 专属提示词结构

每类提示词统一由以下模块动态组合，而不是维护无法复用的一整段大文本：

```text
1. 任务身份：正在识别哪一种资料
2. 版式说明：可能旋转、倒置、倾斜、正反面/两页拼接
3. 当前业务范围：旧车、新车或条件主体材料
4. 允许字段白名单
5. 每个字段的票面标签、读取区域和禁止混淆项
6. 缺失与不确定的处理规则
7. 原始值要求：不得自行做业务归类或补全
8. JSON Schema 和证据坐标要求
9. 禁止审核结论、禁止额外字段、禁止字段名作为值
```

提示词示意：

```text
你正在识别旧车机动车登记证书。图片可能旋转、倾斜，或同时包含第1页和第2页，
请先按印刷文字方向确定阅读方向。只提取白名单字段，值必须是图片中的实际文字。

vehicle.engine_model 只读取“发动机型号”，禁止读取“发动机号码”。
vehicle.vin 只读取“车辆识别代号/车架号码”，禁止读取“车辆型号”。

字段不存在时不要输出；字段存在但看不清时写入 uncertain_fields，禁止猜测。
只输出符合约定结构的 JSON，不输出审核结论。
```

示例值只用于说明格式，不使用本次真实证件中的完整姓名、公司代码、VIN 或联系方式作为提示词样例。

## 8. 识别调用链路改造

### 8.1 已知上传位置走专属提取

当前页面能够识别六类固定上传区域，因此优先使用：

```text
document_type_hint/category_hint + business_scope
        ↓
DOCUMENT_POLICIES[expected_type].build_extraction_prompt(...)
        ↓
QwenClient.extract_fields(...)
```

模型响应仍必须返回 `document_type`，用于反向校验，但不再向模型同时暴露全部资料类型的字段表。

### 8.2 资料类型不匹配处理

出现下列情况时执行一次受控纠错：

- 响应 `document_type` 与上传位置预期类型不一致；
- 返回了白名单外字段；
- 没有任何可用字段且整体置信度低；
- 字段值等于字段路径或字段标题；
- JSON 或字段结构非法。

纠错顺序：

1. 使用预定义原因追加一条针对性指令，再执行一次专属提取；
2. 第二次仍不匹配时，将该材料标记为 `UNCERTAIN`，不静默改成另一类材料；
3. 审核助手显示“上传位置为 X，但模型无法确认资料类型”，让审核员查看原图。

### 8.3 真正未知的额外图片

只有页面无法提供资料类型提示的额外图片才使用分类流程：

```text
轻量资料分类
        ↓
置信度达到阈值
        ↓
命中类型的专属字段提取
```

未知图片允许多一次模型调用；六类固定材料正常情况下仍保持每张图片一次调用，避免整体耗时明显上升。

## 9. 结构化校验与确定性适配

### 9.1 通用校验

- 顶层必须是唯一 JSON 对象；
- `document_type` 必须合法；
- `fields` 只能包含当前材料和业务范围白名单；
- 字段值不能等于规范字段路径、中文字段名或对象字符串；
- `uncertain_fields` 只能包含白名单字段；
- `evidence_regions.field` 必须能对应成功提取或不确定字段；
- 坐标必须位于图片边界内；
- VIN、车牌号、统一社会信用代码只做格式合理性提示，不因格式不完整自动猜补字符。

### 9.2 字段专用校验

- 日期：支持中文年月日、点号、斜杠等输入，代码统一比较格式；
- 金额：去除货币符号和千分位后解析，保留原始票面金额展示；
- 发票号码：拒绝 `invoice.amount`、统一社会信用代码和车辆编号等明显错位值；
- 证明编号：拒绝规范字段路径、二维码密文和无关条码值；
- 发动机型号：保留 OCR 原文，代码处理 `I/1` 等已确认易混淆字符；
- 车辆类型：保留完整车型，代码映射到页面业务类别；
- 所有人：排除地址、身份证明号码和字段标题拼接内容。

### 9.3 数电发票页面适配器

新增明确的确定性适配步骤：

1. 模型只提取票面事实 `invoice.invoice_no`；
2. 确认资料是数电机动车销售统一发票且票面不存在独立发票代码；
3. 为页面核验生成 `invoice.code` 的派生观察值；
4. 派生观察值保留原始图片 ID，同时标记 `derived_from=invoice.invoice_no`；
5. 前端可展示“由数电号码适配”，不将其显示为第二个独立图片字段。

## 12. 测试和评估方案

### 12.1 隐私边界

- 本次真实证件只用于本地人工验证，不原样复制到仓库；
- Git 测试使用脱敏、裁剪或合成样本；
- 测试快照、日志和错误消息不得保存完整身份证号码、电话、统一社会信用代码或 VIN；
- 如建立本地金标集，目录加入 `.gitignore`，并只保存必要字段的脱敏期望值。

### 12.2 单元测试

- 每类专属提示词只包含该 scope 的允许字段；
- 旧车登记证提示包含发动机型号与发动机号码禁止混淆说明；
- 行驶证提示包含注册日期与发证日期禁止混淆说明；
- 发票提示包含价税合计与不含税价禁止混淆说明；
- 缺失字段和不确定字段语义不同；
- 字段路径自回显被拒绝；
- 数电号码只提取一次并由代码派生页面兼容值；
- 模型返回白名单外字段时被拒绝或过滤并记录限制；
- 已知材料正常路径只调用一次模型。

### 12.3 路由和回归测试

- 旧车、新车相邻上传区域不会互相串 scope；
- 上传位置为行驶证但模型返回登记证时，执行一次重试后标记不确定；
- 未知额外图片先分类再进入命中类型的专属提取；
- 单份有效证据仍可参加核验；
- 页面值不计入材料证据数量；
- 原始值用于展示，归一化值用于比较；
- 原有过户、车源、一致性审核路径保持不变。

### 12.4 本次七张材料的人工验收重点

1. 三张旧车材料分别识别为行驶证、登记证书、回收证明。
2. 三张新车材料分别识别为行驶证、登记证书、机动车销售统一发票。
3. 营业执照名称、法定代表人和统一社会信用代码来自正确区域。
4. 报废车辆类型取得三份材料证据，原文均保留，归一化后可与“牵引车”一致。
5. 报废交车日期和证明编号返回票面真实值，不返回字段路径。
6. 报废发动机型号只取登记证“发动机型号”，不取发动机号码。
7. 旧车 VIN 按实际识别到的三份材料逐份展示。
8. 新车燃料类型只使用登记证燃料种类。
9. 新车 VIN 和所有人按实际取得的行驶证、登记证和发票逐份展示。
10. 新车注册日期只使用行驶证注册日期。
11. 发票金额只取价税合计小写值。
12. 数电号码不会与购买方统一社会信用代码、VIN、合格证号混淆。
13. 数电号码通过代码适配到页面发票代码和发票号码，两者不会由模型分别猜测。
14. 终端客户手机号在业务含义未确认时不自动匹配销售方电话。
15. 每个识别值都有正确图片 ID 和可用证据区域。

## 13. 性能、成本和回退

### 13.1 性能约束

- 六类固定材料正常情况维持每张图片一次模型调用；
- 仅在结构非法、类型不匹配或低置信度时重试一次；
- 只有真正未知的图片允许“分类 + 专属提取”两次调用；
- 保留当前并发数、单图超时和整单截止时间限制；
- 记录每类材料的一次成功率、重试率、平均耗时和失败原因，但日志不记录完整敏感值。

### 13.2 灰度与回退

建议把提取策略做成配置项：

```text
slot_targeted：已知位置走专属提示词，推荐默认
merged_unknown：保留当前合并分类提取路径，仅用于快速回退
```

灰度期间对比：

- 资料类型准确率；
- 必需字段召回率；
- 字段串位率；
- `uncertain_fields` 比例；
- 单图平均耗时和整单完成率；
- 人工标记异常数量。

如果专属路径发生系统性回归，可切回旧策略，不需要修改 LangGraph 或前端页面。

## 15. 完成标准

同时满足以下条件才视为改造完成：

1. 固定上传位置的材料使用对应专属提示词，不再默认加载全部资料规则。
2. 七张材料的资料类型均能稳定识别。
3. 日期、证明编号、发票号码和金额不再出现字段路径或字段标题值。
4. 发动机型号、发动机号码、VIN、车辆型号不发生串位。
5. 发票号码、统一社会信用代码、合格证号和 VIN 不发生串位。
6. 原始识别值、归一化值、图片来源和证据区域可追溯。
7. 缺失与看不清能够区分，不因某材料没有该字段制造人工待处理。
8. 数电号码页面兼容映射由代码完成，不依赖模型重复生成。
9. 终端客户手机号只使用发票中明确标注的“电话”字段参与核验。
10. LangGraph、二维码、材料完整性、主体关系和人工审核交互无回归。
11. 全量自动化测试、构建、lint 和 `git diff --check` 全部通过。
12. 未提交真实证件图片和敏感字段到 Git、日志或测试快照。

## 16. 评审结论入口

评审时建议重点确认：

1. 是否同意“已知上传位置走专属提示词，未知图片才分类”的主方案；
